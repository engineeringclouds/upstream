**Check 2: go vet**
```bash
go vet ./...
```
Must produce no output. Common vet issues in new Go code:
- `printf` format string mismatches (`%v` used where `%w` intended in fmt.Errorf)
- Unreachable code after `return`
- Unused variables (though the compiler catches these)
- Incorrect struct tags

**Check 3: gofmt**
```bash
gofmt -l .
```
Must produce no output (empty = all files are formatted). If files are listed, run:
```bash
gofmt -w .
```
Then verify again with `gofmt -l .`.

**Check 4: No log.Fatal in internal/**
```bash
grep -rn 'log\.Fatal' internal/
```
Must return no matches. `log.Fatal` is only permitted in `cmd/upstream/main.go`. If found in internal/, replace with `return fmt.Errorf(...)`.

**Check 5: Error wrapping pattern**
```bash
grep -rn 'errors\.New\|fmt\.Errorf' internal/
```
Review each line. Every `fmt.Errorf` in internal/ must use `%w` for wrapping (not `%v` or `%s`) and must include context in the format string like `"azure: parse: %w"`. Bare `errors.New("something")` is only acceptable for sentinel errors (none expected in Phase 1).

**Check 6: No os.Getenv in internal/**
```bash
grep -rn 'os\.Getenv' internal/
```
Must return no matches. Config is injected via constructors, not read from environment inside packages.

**Check 7: Error discards**
```bash
grep -rn '_ =' internal/
```
Must return no matches (no swallowed errors).

Fix any violations found. Re-run the failing check after each fix. All seven checks must be clean before proceeding to Task 2.
